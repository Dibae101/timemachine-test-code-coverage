Reduce the dataset to the entries proven to work

Keeps only what the smoke run verified end to end. An app survives when at least
one of its APK entries produced a clean coverage report; within a surviving app
only the passing entries are kept.

Result: 8 apps, 10 APK entries, every one validated and every one tested.

    MaterialFBook      19.24%      Omni-Notes      10.58%
    geohashdroid       17.78%      nextcloud        8.63%
    FirefoxLite        13.72%      Twire            2.67%
    AmazeFileManager   13.08%      openlauncher     2.35%

Removed:

  26 source-only checkouts with no class_files.json, whose builds never
     produced compiled classes - not datasets
  10 apps whose entries produce execution data but no report. The cause is in
     report generation rather than the APKs: jacococli cannot parse Java 17
     bytecode, and some entries declared two build variants at once so JaCoCo
     rejected duplicate class names
   4 APK entries inside surviving apps that report a class mismatch. Those pair
     an upstream-published APK with locally compiled classes, so the coverage
     they report is wrong rather than merely incomplete. The -rebuilt.apk of
     each pair is kept
  18 smoke result directories belonging to any removed entry

geohashdroid and openlauncher keep both their entries: published APK and local
rebuild agree class for class, so both report correctly.

Submodules are de-registered for removed apps, leaving 8 in .gitmodules. The
summary tables are rewritten to match: smoke_summary.csv 31 rows to 11,
probe_summary_all.csv 28 to 10.

instrumented_apps drops from 3.1 GB to 399 MB and results from 168 MB to 95 MB.
Nothing is lost permanently - every removed tree stays in git history, and the
builder can rebuild any of them from dataset_builder/subjects.json and
modern_subjects.json.
