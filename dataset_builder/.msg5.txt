Recover 10 datasets and fix the two faults that blocked their reports

Restores the apps removed in 67f207662 and repairs what actually stopped them,
taking the verified set from 8 apps to 13. All 18 now produce a coverage report.

Fault 1: the bundled jacococli 0.8.6 cannot analyse Java 17 bytecode and aborts
with "Unsupported class file major version 61". Added JaCoCo 0.8.13 as
fuzzingandroid/libs/jacococli-0.8.13.jar; smoke_test_dataset.sh now uses it and
honours a JACOCO override. This alone recovered AnkiDroid, StreetComplete and
newpipe.

Fault 2: entries declared more than one build variant's class output, so JaCoCo
refused to build the report: "Can't add different class with same name". Two
things were needed to fix it properly:

  * validating with a real `report` run rather than `classinfo`. classinfo walks
    classes independently and never builds the coverage bundle where the
    collision is detected, so it happily accepted directory sets that report
    then rejected. This cost a full pass to discover.
  * preferring the variant the APK was actually built from, read from the gradle
    task recorded in status-*.csv. Choosing a different flavour still produces a
    report, but every class that differs is excluded as "does not match":
    Wikipedia lost 167 classes that way and reported 0.75%. With devDebug
    selected it reports 3.41% with nothing excluded.

Generated resource classes (R, R$*) are also dropped from declarations. They
carry no meaningful coverage and collide across modules and flavours; 3531 were
removed across the set.

Clean pass, 13 apps:
  MaterialFBook 19.24%, geohashdroid 17.78%, StreetComplete 15.20%,
  FirefoxLite 13.72%, AmazeFileManager 13.08%, Omni-Notes 10.58%,
  nextcloud 8.63%, commons 7.57%, newpipe 7.57%, AnkiDroid 4.11%,
  Wikipedia 3.41%, Twire 2.67%, openlauncher 2.35%

Five more produce usable reports with a handful of classes excluded:
  Vinyl-Music-Player 16.96% (4), APhotoManager 8.76% (13),
  Open-Food-Facts 4.88% (3), open-event-attendee-android 4.11% (3),
  Fedilab 0.11% (11)

The 10 restored apps also needed their .gitmodules entries restored. Their
upstream gitlinks came back with the directories, and 10 gitlinks against 8
declarations is exactly the phantom-submodule state fixed earlier in 96f13356;
all 18 entries are declared again.
